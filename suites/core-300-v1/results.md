# 每模型 300 题：已完成结果

下面的主表只列出真正完成同一批 300 题、且采用冻结本地推理协议的模型配置。300 是**每个模型配置**的题数，不是所有模型合计。另有一个产品渠道扩展对照；它复用同题、逐字相同的用户提示词和同一评分器，但平台系统上下文及部分推理参数不同，因此单独列出。

## 汇总

阅读表格前先说明模型名与配置：Qwen3.8-27B 中的 `3.8` 是模型系列版本标识，`27B` 表示约 270 亿参数；ApoDEx-1.1-mini 中的 `1.1` 是模型版本号，`mini` 是发布者给出的尺寸标签，不代表本文验证过的参数量；Qwen3.8-Flash-Next 中的 `3.8` 同样是系列版本标识，`Flash-Next` 是该模型变体名称。

`Q4_K_M` 是 4-bit 权重量化配置：`Q4` 表示以 4-bit 为主，`K` 表示 K-quants 分块混合量化家族，`M` 表示 Medium（中等）配方；`Q8_0` 中的 `Q8` 表示 8-bit，`0` 表示基础配方。两者使用 GGML Universal File（GGML 通用文件，简称 GGUF）本地模型文件；GGML 是开源本地推理引擎 `llama.cpp` 所用底层张量库的项目名。GPTQ 是面向生成式预训练模型的训练后权重量化方法，`Int4` 表示 4-bit 整数权重。`UD-Q4_K_XL` 是社区发布的 4-bit GGUF 混合量化配方名称，其中 `4` 表示 4-bit 主量化档，`XL` 是配方尺寸标签，其余字母也属于配方名称，不代表本文可横向比较的独立数值。

下文使用的 McNemar 检验只比较两个配置在同一道题上的对错分歧；其中 `p` 是在“两个配置成功率没有差异”假设下出现当前或更极端配对差异的概率，通常以 0.05 作为是否检出差异的参考阈值。

## 配对结论

1. **Qwen3.8-27B 4-bit 对 8-bit：未检出显著差异。**4-bit 为 245/300，8-bit 为 238/300；4-bit 独赢 14 题，8-bit 独赢 7 题，双侧精确 McNemar `p=0.189247`。这不能写成“4-bit 已证明更聪明”，也没有证明两者统计等效。
2. **ApoDEx 对 Qwen3.8-27B 4-bit：本批题上 Qwen 显著更高。**ApoDEx 为 207/300，Qwen 为 245/300；ApoDEx 独赢 18 题，Qwen 独赢 56 题，双侧精确 McNemar `p=0.00001109`。
3. **Qwen Flash-Next 对 Qwen3.8-27B 4-bit：未检出显著差异。**Flash-Next 为 247/300，旧 27B 基线为 245/300；Flash-Next 独赢 17 题，旧基线独赢 15 题，双侧精确 McNemar `p=0.8601`。247 对 245 不能解释为已经证明 Flash-Next 胜出。

## 基线复用说明

Qwen3.8-27B 4-bit 的 245/300 是 2026-08-21 至 2026-08-22 完成的冻结基线。ApoDEx 和 Flash-Next 后续比较时，各自新跑同一批 300 题；Qwen 基线没有重复运行。对照前逐条核对题目编号、冻结任务哈希与提示词哈希，均为 300/300 一致。

因此，表中四行可以说明这批固定题上的历史表现，但不能把不同日期、硬件状态和推理运行时的速度差异解释为纯模型速度差异。

## 同题同判分的渠道扩展对照（非严格同协议）

Hy4 Preview 是 2026-08-29 通过腾讯 WorkBuddy 调用时显示的预览模型别名；名称中数字 4 的含义平台没有披露，不能把它当作已验证的固定版本号。当时的 WorkBuddy 应用版本是 5.4.2。本次选择最高推理档位，关闭工具，每题使用一个新会话。它完成了同一批 300 题，逐字相同的用户提示词和评分器均与主表一致，但平台系统上下文不同，WorkBuddy 也不开放温度、随机种子、最大输出长度或不可变的后端版本号。因此，它不能并入上面的严格协议主表，也不能据此断言某个固定模型版本在完全相同条件下胜出。

代码分项包括 HumanEval Plus（HumanEval 增强版，HumanEval+）Python 函数生成基准的 72/75（96.00%），以及 Mostly Basic Python Problems Plus（基础 Python 编程题增强版，MBPP+）的 57/75（76.00%）；两个加号都表示增加了更强测试。与主表中的 Qwen3.8-27B 4-bit 冻结基线逐题配对后：

- 全部 300 题：Hy4 Preview 为 259，Qwen 基线为 245；Hy4 独赢 26 题，Qwen 独赢 12 题，差值为 4.67 个百分点。双侧精确 McNemar 检验 `p=0.0336`，配对自助法的 95% 置信区间为 0.67–8.67 个百分点。
- 代码 150 题：129 对 125，双侧精确 McNemar `p=0.4807`，未检出差异。
- 困难推理 150 题：130 对 120，双侧精确 McNemar `p=0.0414`；本次总分差异主要来自这一分项。

McNemar 检验是一种只看两套配置在同一道题上谁对谁错的配对检验；`p` 值用于衡量“真实成功率没有差异”时出现当前或更极端配对差异的概率。配对自助法是重复重采样同一批成对题目，用于估计分差的不确定范围。

代码与困难推理的分项 `p` 值是探索性拆分，未做多重比较校正，不能单独当作确定性的分项胜负证明。

这里能支持的结论是：**在这次同题、逐字相同的用户提示词和同一评分器的 WorkBuddy 产品入口扩展对照中，Hy4 Preview 的点估计高于 Qwen 4-bit 基线，且配对总分差异达到 `p=0.0336`；不能把它改写为严格同推理协议下已经证明 Hy4 更强。**原 Qwen 基线设置了 8,192 tokens 最大输出长度并出现 24/300 次长度截断，而 WorkBuddy 不开放同一输出上限或截断字段，这可能对比较有利于 Hy4。云端入口和本地推理运行时的速度、token 用量也不做比较。
